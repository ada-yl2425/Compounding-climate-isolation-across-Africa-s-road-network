## 根因与最小修复

- `result1/network_pipeline.py` 的原 `_merge_endpoints` 只跳过同一线段两端的直接 union；经第三方端点仍可能传递合并。原 Kenya 图工程 QA 对 358,791 条筛后候选记录 294,559 条自环跳过。
- 保持 `SNAP_THRESHOLD_DEG = 0.0045` 不变，联合查找在合并两个节点簇前检查它们是否分别包含同一条道路的两端；若有则拒绝该合并。物理线段不会因端点吸附成为自环。此修复可能增加节点数量并改变连通分量，必须在 Kenya 全图和后续国家验收其幅度，不能把它视为纯计算加速。
- 物理道路以 `df_edges` 每条 `road_id` 一行保留；`G0`、`G1` 仍是为现有最短路算法构造的简单图，分别投影为同一端点对中正常/极端情景最小旅行时间的道路，并在两图中保留各自的 `road_id`。两情景可选择不同的平行道路。`G_conn` 是端点对层面的无权简单图。
- `hpc/qa_kenya_graph_build.py` 改为按端点对验证每个情景的最小权/`road_id` 投影，验证物理表道路 ID 唯一、速度表匹配、无自环、正有限权重、有效候选线段全保留。
- `result1/run_africa_layer.py` 原有独立图构建器也采用相同的端点约束及 G0/G1 独立平行路投影，并在每个情景的图边标出物理 `road_id`；合成跨境边明确标记 `synthetic=True` 和独立的 `synthetic_border_*` ID。跨境生成距离/速度阈值均未改变。该脚本没有输出国家级全物理边表，因此泛非固定物理路线仍需单独建立 road_id→极端权重 crosswalk。

## 下游兼容性与待决口径

| 消费环节 | 多物理边表下的状态 |
|---|---|
| `extract_lcc`、OD 最短路、网络效率 | 可使用情景各自的简单图最小权投影；物理边表按端点保留。须通过 Kenya 全图对齐闸门。 |
| 固定路线 vs 重新选路（C04） | 固定路线必须锁定 G0 路径每一步的**物理 `road_id`**，并从物理表读取该路的 `w1`；仅锁节点序列、再查 G1 会在平行边处暗中换路。 |
| 泛非跨境 OD | 国家内图已采用同样约束，但旧 checkpoint 必须强制重建，不能载入旧拓扑；合成跨境边不是源道路，C04 固定路线应单列并标注其不变权重。 |
| `identify_critical_roads` | 简单图的 bridge 是端点对桥；如该端点对有多条物理路，不应直接称其中任一条为单道路桥。BC 同样是端点对级。需要确定物理道路分配/评分口径。 |
| `percolation_analysis` | 当前 `(u,v)` 字典使平行道路互相覆盖，一次 `remove_edge` 又移除整个端点对，故不能直接用于按“道路边数”定义的渗流或干预。需先重构物理边失效及预算口径。 |
| `spatial_clustering`、`save_critical_roads` | 前者将端点对 BC/桥标记重复赋给平行道路；后者只保存 G0 投影中的一条道路。若报告物理道路瓶颈，必须先定义映射。 |

因此 Kenya 图 QA 通过仍只是图输入/投影一致性证据，**不是 C03 瓶颈、渗流或干预模型的放行条件**。正式重算至少还需全图输入验收、上述物理道路方法选择及相应测试。
